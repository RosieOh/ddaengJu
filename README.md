# 네이버 파워링크 노출순위 모니터

키워드를 넣으면 네이버 모바일 파워링크에서 **엔카(및 경쟁사)가 몇 위에 노출되는지**를
자동으로 세어 줍니다. 수작업으로 검색하고 '더보기'를 눌러 가며 순위를 세던 일을 대체합니다.

---

## 1. 실행 방법

`run.bat` 을 더블클릭하면 됩니다. 필요한 패키지가 없으면 알아서 설치하고,
브라우저에서 <http://localhost:8000> 이 열립니다.

수동으로 실행하려면:

```bat
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

같은 사무실 안 다른 PC에서도 `http://<서버PC의IP>:8000` 으로 접속할 수 있습니다.

## 2. 쓰는 법

### 화면은 기기에 따라 두 벌입니다

화면 구성(조회 · 분석 · 설정)은 어디서나 같고, **껍데기만** 바뀝니다.
기기마다 정보구조가 달라지면 쓰는 사람이 헷갈리기 때문입니다.

| | 폰·태블릿 (~1023px) | PC (1024px~) |
|---|---|---|
| 이동 | **하단 탭바** | **좌측 메뉴** (건수 표시) |
| 상단 | 현재 화면 이름 | 제품명 + 자동수집 상태 |
| 하단 | — | **상태바** (최근/다음 수집, 키워드·측정 건수) |
| 결과 | 리스트 (키워드 + 큰 순위) | **고밀도 표** (29px 행, 열 구분선) |
| 광고 목록 | 아래에서 올라오는 **시트** | 행 아래 인라인 펼침 |
| 주 동작 | 엄지 닿는 자리에 고정 | 도구 막대 맨 앞 |

- 폰에서는 입력창 글자가 16px입니다 — 그보다 작으면 iOS가 포커스할 때 화면을 확대합니다.
- 노치·홈 인디케이터 영역(`env(safe-area-inset-*)`)을 피해서 배치됩니다.
- 터치 타겟은 화면 폭이 아니라 **입력 방식**(`pointer: coarse`)으로 판단해 키웁니다.
  터치 노트북은 넓어도 손가락으로 누르고, 좁은 창의 마우스는 정확하기 때문입니다.
- 차트는 좁은 화면에서 줄여 뭉개는 대신 **자기 칸 안에서만 옆으로 스크롤**합니다. 본문은 가로로 밀리지 않습니다.
- `?view=analysis` 로 특정 화면을 바로 열 수 있습니다.

### 첫 화면
처음 열면 스플래시가 뜹니다. 광고 슬롯 15칸이 세로로 서 있고, 마커와 숫자가 **15위에서 1위까지
직접 세며 올라갑니다.** 손으로 세던 그 일을 이 도구가 대신한다는 뜻입니다.

- 한 브라우저 세션에 **한 번만** 뜹니다. 클릭·Esc·`건너뛰기`로 언제든 넘길 수 있습니다.
- 다시 보고 싶으면 왼쪽 위 **제목을 클릭**하세요.
- 운영체제에서 '동작 줄이기'를 켜 두었다면 카운트 없이 마지막 장면만 잠깐 보여주고 닫힙니다.

### 순위 조회
키워드를 콤마나 줄바꿈으로 구분해 넣고 **순위 조회**를 누릅니다.
엑셀에서 셀 여러 개를 복사해 그대로 붙여넣어도 인식합니다(탭·줄바꿈 모두 구분자로 처리).

- 키워드를 눌러 **파워링크 광고 목록 전체**를 1위부터 펼쳐 볼 수 있습니다. 추적 업체는 자동 강조됩니다.
- `?q=중고차팔기,내차팔기` 형태로 주소창에 넣으면 열자마자 바로 조회합니다. 즐겨찾기로 걸어두고 쓰세요.

### 분석 화면
조회 결과 아래에 분석 영역이 붙습니다. 위쪽 **필터 한 줄(기간·키워드)** 이 아래 차트 전부를 함께 바꿉니다.

| 구성 | 읽는 법 |
|---|---|
| **KPI 타일** | 기준 업체의 평균 순위 / 첫 페이지 노출 / 상위 3위 / 순위밖. 직전 수집 대비 증감이 화살표로 붙습니다 |
| **키워드 × 업체 히트맵** | 진할수록 상위. 어느 키워드에서 누가 앞서는지 한눈에 봅니다 |
| **순위 변화 (덤벨)** | 옅은 점 = 직전, 진한 점 = 현재. 선 길이가 그대로 변동폭입니다 |
| **순위 추이 (라인)** | 위로 갈수록 상위. 점선이 첫 페이지(15위) 경계입니다 |
| **시간대별 평균 순위** | 0~23시 중 언제 밀리는지. 가장 좋은/밀리는 시간대를 표시합니다 |

모든 차트는 마우스를 올리면 값이 뜨고, 오른쪽 위 **표로 보기**로 숫자를 그대로 볼 수 있습니다.
범례를 클릭하면 해당 업체 선을 껐다 켤 수 있습니다.

### 리포트 추출
필터 줄 오른쪽에서 두 가지로 내보냅니다.

- **리포트(HTML)** — 파일 하나로 끝나는 단독 리포트. 서버 없이 더블클릭으로 열리고 메일 첨부로 그대로 공유됩니다.
  화면과 **같은 차트 코드**를 쓰므로 대시보드와 어긋나지 않습니다. 경쟁 구도·변동성 표까지 들어갑니다.
- **리포트(엑셀)** — `요약`(KPI + 색조 히트맵) · `순위추이`(키워드별 라인차트) · `시간대별`(막대차트) ·
  `변동성` · `순위이력` 5개 시트. 이미지가 아니라 **엑셀 네이티브 차트**라 받는 쪽에서 축·기간을 바꿔 볼 수 있습니다.

### 자동 수집
설정 패널에서 자동수집 키워드를 저장해 두면 **매시 정각에 자동으로 순위를 수집**하고,
시간대별 추이가 쌓입니다. 순위 변동이 잦은 시간대를 파악해 입찰가 조정에 쓸 수 있습니다.

### 추적 업체
설정에서 업체를 추가/삭제합니다. **첫 번째 업체가 기준 업체**로 표에서 강조됩니다.
매칭어는 광고의 **업체명·도메인**에 대해 부분 일치로 판정합니다(예: `엔카, encar`).
광고 제목·설명은 매칭 대상에서 제외했습니다. 경쟁사 광고 문구에 '엔카'가 언급되면
오탐이 나기 때문입니다.

## 3. 배포 — 반드시 가정용 회선에서 돌려야 합니다

**네이버는 접속한 IP에 따라 다른 광고 세트를 내려줍니다.** 데이터센터 IP로 요청하면
광고가 40%가량 적게 나오고, 그만큼 순위가 실제보다 훨씬 좋게 찍힙니다.
같은 시각 실측 비교입니다.

| 키워드 | 가정용 IP | 데이터센터 IP(GitHub Actions) |
|---|---|---|
| 중고차팔기 | 광고 73개, 엔카 **8위** | 광고 44개, 엔카 **3위** |
| 내차팔기 | 광고 56개, 엔카 **5위** | 광고 33개, 엔카 **2위** |
| 내차시세조회 | 광고 35개, 엔카 **6위** | 광고 25개, 엔카 **1위** |

두 환경에서 각각 두 번씩 돌려 값이 완전히 같았습니다. 광고 로테이션이 아니라
IP로 갈리는 결정적 차이입니다.

**따라서 클라우드 배포(GitHub Actions, Railway, Render, Fly.io …)는 전부 같은 문제를 안습니다.**
전부 데이터센터 IP이기 때문입니다. 잘못된 순위로 판단하느니 안 쓰는 편이 낫습니다.

### 쓸 수 있는 방법

| 방법 | 데이터 | 접근성 |
|---|---|---|
| **로컬 실행** (`run.bat`) | 정확 | 그 PC에서만 |
| **self-hosted 러너 + Pages** | 정확 | 어디서나 (읽기 전용) |
| **로컬 + Cloudflare Tunnel** | 정확 | 어디서나 (전체 기능) |

`.github/workflows/collect.yml` 은 만들어져 있지만 **비활성 상태**입니다.
가정용 회선 PC에 self-hosted 러너를 등록하고 `runs-on: self-hosted` 로 바꾸면
그대로 살아납니다. 그 PC가 켜져 있는 동안만 수집됩니다.

## 4. 알아 두실 점

**순위는 호출할 때마다 흔들립니다.**
네이버 파워링크는 입찰가 외에 광고 로테이션이 걸려 있어, 같은 조건으로 연속 호출해도
15개 중 3~4개가 다른 광고로 바뀝니다. 그래서 이 도구는 키워드당 기본 **3회 측정 후
중앙값**을 순위로 씁니다. 측정 사이에 순위가 흔들린 키워드에는 `변동` 표시가 붙고,
표시에 마우스를 올리면 실제 측정값 3개를 볼 수 있습니다.

**모바일 기준입니다.**
수집 대상은 `m.ad.search.naver.com` 의 모바일 파워링크이며, 1페이지에 15개가 노출됩니다.
16위 이상은 사용자가 '더보기'를 눌러야 보이는 자리입니다. PC 파워링크는 페이지 구조가
달라 순위가 따로 매겨지므로, 필요하시면 별도 파서를 추가해야 합니다.

**과도한 호출은 차단 위험이 있습니다.**
동시 요청 수 기본값 5, 페이지 사이 랜덤 지연 0.25~0.7초로 제한되어 있습니다.
설정에서 올릴 수 있지만 권장하지 않습니다.

### UI/UX 규칙은 측정으로 확인합니다

[ui-ux-pro-max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 규칙셋(접근성·터치·레이아웃·폼)을
브라우저에서 직접 측정해 통과시켰습니다. 체크리스트에 표시만 하지 않고 값을 재서 확인합니다.

측정 조건: **폰 세로 375 / 폰 가로 812 / 데스크톱 1440** × **라이트·다크** × **세 화면**, 그리고 시스템 글꼴 200%.

| 우선순위 | 항목 | 결과 |
|---|---|---|
| 1 접근성 | 텍스트 대비 (본문 4.5:1, 큰 글씨 3:1) | 위반 **0** |
| 1 접근성 | 스킵링크·제목단계·폼라벨·아이콘 라벨 | 위반 **0** |
| 2 터치 | 타겟 44px (터치 기기) | 위반 **0** |
| 3 성능 | CLS (기준 0.1) | **0.03** |
| 5 레이아웃 | 가로 스크롤 (글꼴 200% 포함) | **0px** |
| 6 타이포 | 모바일 본문 16px · 줄높이 1.55 | 통과 |
| 9 내비 | 뒤로가기·딥링킹·탭 5개 이하 | 통과 |
| 10 차트 | 범례·툴팁·표 보기·색 단독 아님 | 통과 |

### 화면 주소가 남습니다

화면을 바꾸면 주소도 함께 바뀝니다(`?view=analysis`). 그래서

- **뒤로가기**가 이전 화면으로 돌아갑니다. 폰에서 시트가 열려 있으면 시트부터 닫힙니다.
- 특정 화면을 링크로 보내거나 즐겨찾기에 걸 수 있습니다.

인접 타겟 8px 규칙에서 **리스트 행끼리·탭바 칸끼리**는 위반으로 잡히지만 그대로 뒀습니다.
둘 다 전체 폭 타겟이라 잘못 눌러도 이웃한 유효 타겟에 떨어지는 표준 패턴입니다.
데스크톱의 44px 미만 컨트롤도 그대로 둡니다 — 터치 규칙이고, 이 프로젝트는
화면 폭이 아니라 **입력 방식**(`pointer: coarse`)으로 타겟 크기를 정합니다.

### SVG 글자색은 반드시 인라인 style 로 줍니다

`.viz text { fill: … }` 같은 **CSS 선언은 SVG 의 `fill` 속성을 항상 이깁니다.**
히트맵 칸 글자를 `fill="…"` 속성으로 주면 조용히 회색으로 덮여 안 읽힙니다.
`style="fill:…"` 로 줘야 합니다. 칸 색과 글자색은 대비를 계산해 `--viz-qN` ↔
`--viz-qN-ink` 로 짝지어 뒀고(최저 5.06:1), 다크 모드에서 램프가 뒤집히면
글자색도 함께 뒤집힙니다.

### 모션은 상태를 설명할 때만 씁니다

장식용 애니메이션은 넣지 않았습니다. 움직이는 것에는 전부 뜻이 있습니다.

| 움직임 | 뜻 |
|---|---|
| 스플래시 카운트 15→1 | 이 도구가 하는 일 (유일한 연출 장면) |
| 결과 행이 차례로 나타남 | 목록이 목록으로 도착함 (총 지연 216ms 상한) |
| 바뀐 순위 칸만 잠깐 물듦 | **어디가 달라졌는지** |
| 추이 선이 왼쪽부터 그려짐 | 시간순으로 쌓인 데이터 |
| 덤벨의 '현재' 점이 밀려옴 | 이동 거리 = 순위 변화량 |
| 상세가 트랙으로 펼쳐짐 | 어디에 붙은 내용인지 |

전부 `prefers-reduced-motion`을 존중합니다. 동작 줄이기를 켜면 즉시 최종 상태로 갑니다
(선이 사라지거나 내용이 감춰지지 않습니다).

### 차트 색상은 검증된 팔레트입니다

계열 색은 눈대중으로 고르지 않고 색각 이상(CVD) 분리도·명도대·대비를 스크립트로 검증해
통과한 순서를 그대로 씁니다(라이트 `#ffffff` / 다크 `#1c1c1c` 표면 양쪽 통과).
**슬롯 순서 자체가 안전장치**이므로 `viz.css` 의 `--viz-s1`~`--viz-s8` 순서는 임의로 바꾸지 마세요.
색 대비가 낮은 슬롯이 있어 모든 차트에 직접 라벨과 표 보기를 함께 넣었습니다.
색은 업체(개체)에 고정되므로, 범례로 계열을 껐다 켜도 남은 선의 색은 바뀌지 않습니다.

### 순위를 어떻게 알아내는가

파워링크 목록 HTML 에는 각 광고마다 아래 형태로 **절대 순위가 그대로** 들어 있습니다.

```
nclk(this, 'sct.title', 'nad-a001-01-000000494587285', 13)
                                                       └─ 순위
```

`&page=2`, `&page=3` … 파라미터로 16위 이후 구간을 직접 요청할 수 있어
'더보기' 클릭을 흉내 낼 필요가 없습니다. 그래서 Selenium 같은 브라우저 자동화 없이
순수 HTTP 만으로 동작하고, 키워드 1개 전량 수집이 약 1초에 끝납니다.
마크업이 바뀌어 `nclk` 가 사라지면 페이지 내 등장 순서로 순위를 계산하는 안전망이 있습니다.

### 주요 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/search` | 즉시 순위 조회 (이력 저장 포함) |
| GET | `/api/detail?keyword=` | 키워드 1개의 광고 목록 전량 |
| GET | `/api/analytics?hours=` | 대시보드 지표 묶음 (KPI·히트맵·추이·시간대·변동성·경쟁구도) |
| GET | `/api/history?keyword=&hours=` | 추이 시계열 (원본) |
| GET | `/api/export.xlsx?hours=` | 엑셀 리포트 (차트 임베드) |
| GET | `/api/report.html?hours=` | 단독 HTML 리포트 (`&download=false` 로 브라우저에서 바로 보기) |
| GET/POST | `/api/config` | 설정 조회/저장 |
| GET | `/api/status` | 스케줄러·저장소 상태 |
| POST | `/api/run-now` | 자동수집 1회 즉시 실행 |
